# 厂商报告适配与提交预览

在漏洞列表勾选 1–20 条记录后点击「提交预览」，或从漏洞详情进入。每个漏洞、每个目标项目各保留一份当前草稿；刷新页面后可以继续编辑。

## 使用流程

1. 新增厂商规则：填写项目名称、官方 HTTPS 提交入口、规则来源，粘贴官方范围/类型限制和报告模板。添加厂商明确要求的固定字段，例如受影响版本、测试账号角色。
2. 检查证据快照。草稿默认取漏洞的详细报告（没有详细报告时使用摘要与证据），不自动读取流量文件、截图或任务目录。
3. 可手动编辑，也可点击「智能适配」。确认该项目允许使用所选模型后，LLM 根据规则和漏洞类型整理报告、提出额外字段、标出缺失材料。生成会替换当前草稿，失败时保留原稿。
4. 在预览、字段编辑、证据三个标签之间切换；保存编辑，核对所有事实和来源。
5. 满足检查条件并人工确认后，下载 Markdown 材料，再打开官方提交页面完成投递。

## 当前范围

此版本是实际保存数据的报告准备流程，不是自动投递功能。没有调用 HackerOne 创建报告接口、自动填写第三方表单、上传附件或保存 HackerOne 凭据。HackerOne 和厂商网页的规则均需手动导入和维护；不自动读取私有项目或推断项目权限。

LLM 字段来源是摘要、证据、详细报告的来源标记，不是逐句引用或事实验证。程序不能证明漏洞在范围内，也不能证明模型没有幻觉；最终内容仍需人工复现和核对。

## 数据与保护

- 新表 `submission_profiles` 保存规则和字段；`submission_drafts` 保存当前草稿、脱敏快照、来源哈希及版本。启动时以 `CREATE TABLE IF NOT EXISTS` 增量创建，不改写已有漏洞和任务。
- 同一漏洞与项目重复准备会复用草稿。乐观版本控制防止旧标签覆盖新编辑；生成期间来源或规则变化会拒绝保存。证据、规则、漏洞状态改变后，确认和导出会重新检查。
- 确认要求：漏洞为 `confirmed`，严重性为 High/Critical，详细报告未落后于证据，必填材料完整，草稿来源与规则版本一致。改变正文或字段会清除确认状态。
- 仅保留当前草稿，不提供历史版本恢复。重建或重新生成前请导出/复制需要保留的内容。
- 自动隐藏常见凭据格式，但不能代替人工检查个人信息或其他敏感材料。预览不执行 HTML，不加载正文中的外部图片，也不自动访问正文链接。
- 所有新增 API 使用应用现有认证。模型调用明确选择现有 LLM 配置；直接绑定该配置，不使用全局供应商故障切换池。OpenRouter 在该配置内部的渠道限制仍由现有配置负责。
- 生成无工具调用，最多 110 KB 输入、4096 输出 token（配置更低时取更低值）、80 秒期限；单个服务实例同一时刻只允许一份报告生成。上游重试沿用现有提供方设置。
- 草稿保存在 PostgreSQL。归档任务时会一并保存草稿与其引用的厂商规则；恢复优先沿用当前厂商规则。没有为此增加常驻服务或第三方依赖。

## 验证

```sh
# 不设置 DSN 时，数据库集成测试会跳过。必须使用隔离测试库。
ARTEX_PG_DSN='postgres://.../artex_test?sslmode=disable' go test -race ./submission ./server -run 'Test(Submission|RedactDisclosure|ModelCannot|SnapshotAnd|ProfileValidation|ModelMissing|ModelOmitted)'
cd web
npm run build:static
```

浏览器流程验证使用真实 Go API、临时 PostgreSQL 和仅监听本机的模拟模型接口，覆盖新增规则、固定字段、脱敏、生成、编辑保存、刷新恢复、确认下载以及桌面/手机布局；不向真实厂商发送报告，也不消耗模型额度。
